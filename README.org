* Quickstart: command line

  Start here to confirm the setup works before moving to =notebook.ipynb=
  for real interactivity (cue lists, autostep, arm/advance controls).

  There's no CLI script / ~__main__~ entry point yet — =src/= is a plain
  library, driven from a Python REPL (or the notebook). Run these from
  the project root.

** 1. Confirm the Motif port is visible

#+begin_src python
import sys; sys.path.insert(0, "src")
import mido
print(mido.get_output_names())
# expect to see a port with "motif" in the name somewhere (exact casing varies by machine)
#+end_src

  If the Motif isn't listed, check the USB/DIN connection before going
  further — nothing below will work without it.

** 2. Send one tuning change

#+begin_src python
from catalog import Catalog
from midi import MidiOut

catalog = Catalog("resources")
midi_out = MidiOut()   # prefers any port with "motif" in the name; falls back to first port
print("using port:", midi_out.port_name)

scale1 = catalog.scale_by_name("SLENDROB3")
scale2 = catalog.scale_by_name("HEXANY15")
#+end_src

  The Motif often powers on in a confused tuning state, so a single send
  can look like nothing happened even when it worked — you need to see
  it land on something specific and known. Send scale1, then look up at
  the Motif's display before doing anything else:

#+begin_src python
midi_out.send_sysex(catalog.sysex_for_scale(scale1.index))
print("sent", scale1.name)
#+end_src

  Confirmed a change? Now send scale2 and look again — a second,
  different change rules out a fluke (e.g. a coincidental match with
  whatever confused state it powered on in):

#+begin_src python
midi_out.send_sysex(catalog.sysex_for_scale(scale2.index))
print("sent", scale2.name)
#+end_src

  =sysex_for_scale= automatically wraps the data in the required
  open/close framing messages — see "Critical sysex detail" in CLAUDE.md
  if you ever need to bypass the wrapper.

** 3. Send one voice/program change

#+begin_src python
voice = catalog.voice_by_name("PRE2", "Airy_Nylon")
msgs = catalog.sysex_for_voice(voice.bank, voice.index)
midi_out.send_sysex(msgs)
print(f"sent {len(msgs)} messages for {voice.bank}:{voice.name}")
#+end_src

  Swap in any name from that bank — use ~catalog.voices("PRE2")~ to list
  what's available if you don't have a name handy.

** 4. Start the notebook

  Once one tuning send and one voice send both land correctly, move to
  =notebook.ipynb= for the real workflow: an arm/disarm toggle, a loaded
  cue list (=cuelists/gamelan_pads_24.csv= by default — edit =CUELIST_PATH=
  in Cell 1 to change it), manual advance per pointer (tuning/voice
  independently or together), and optional autostep. The
  =PerformanceState= class in =src/state.py= is the same object driving
  the widget — the REPL calls above are just the =Catalog=/=MidiOut=
  layer underneath it, without the arm/cue-pointer bookkeeping.

  Install Jupyter and ipywidgets into your venv first if you haven't
  (not yet pinned in =requirements.txt=):

#+begin_src bash
python3 -m pip install jupyter ipywidgets
#+end_src

  Then, from the project root, with the venv active:

#+begin_src bash
jupyter notebook
#+end_src

  This opens a browser tab to Jupyter's file browser — click
  =notebook.ipynb=. Run the cells top to bottom with Shift-Enter:

  - Cell 1 (config) — just sets paths, no output expected.

  - Cell 2 (port check) — prints available MIDI ports; confirm the Motif
    shows up.

  - Cell 3 (main widget) — builds =catalog=, =state=, =midi_out=, and
    displays the widget. Any error here points at whichever piece failed.

  You do not need to call anything in =src/= by hand once this is
  running — arm, advance, jump, and autostep are all driven from the
  widget itself.

  To shut down cleanly: close the browser tab, then =Kernel -> Shut Down=
  from the Jupyter interface (or =Ctrl-C= twice in the terminal that's
  running =jupyter notebook=).

  Cue list generation (=src/cuelist_gen.py=) for building new random /
  cross-product / zipped cue lists from filtered scale and voice subsets
  is exposed in the notebook's cuelist-generator cell (Cell 4).

* Diagnostics (raw sysex, no Catalog/MidiOut wrapper)

  Lower-level checks, useful if step 2/3 above doesn't produce any
  reaction on the hardware and you want to isolate whether the framing
  itself is reaching the Motif.

#+begin_src python
# Diagnostic: send the tuning-open framing message alone.
# If the Motif briefly mutes or its display flickers, the port is correct.
open_msg = bytes([240, 67, 0, 107, 0, 0, 14, 47, 0, 67, 247])
midi_out.send_sysex([open_msg])
print("sent:", open_msg.hex(' '))
#+end_src

  Then, to send one complete scale with framing:
#+begin_src python
# Send SLENDROB3 tuning (framing + 25 data messages + framing close)
scale = catalog.scale_by_name('SLENDROB3')
msgs = catalog.sysex_for_scale(scale.index)
print(f"{len(msgs)} messages  |  first: {msgs[0].hex(' ')}")
midi_out.send_sysex(msgs)
#+end_src

  The msgs[0] hex should now be =f0 43 00 6b 00 00 0e 2f 00 43 f7= (the
  open frame), not the raw tuning data. The 20ms inter-message delay is
  still in place, so the full 27-message sequence (1 open + 25 data + 1
  close) takes about 0.5s.

  Known-good name pair for testing: =HEXANY15=, =PRE1:Early_Fusn=
